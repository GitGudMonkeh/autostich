## Part 2 — the zero-delta gates

### 2.1 Below 1280 px — zero, and it took a second attempt to get there

**Six cells (360 × 800 · 390 × 844 · 1279 × 800, both languages), everything compared:** the
wordmark's box, its text, its resolved `--wm-size`, font size, line height, letter-spacing and margin;
the document's scroll height; and the box of **every** child of `.hub-root`.

| | result |
| --- | --- |
| cells with any delta | **0 of 6** |
| boxes contributed by `.as-brandgrid` below the threshold | **0** |
| boxes contributed by `.as-lockup` below the threshold | **0** |

**The first version was not zero, and that is the finding** (C2-F03). It kept both variants in the
DOM and hid one with a media query — which needs the glyph to sit in an inline element of its own,
and **an extra inline box moved the wordmark's width by 0.02 px in two of the six cells.** Invisible;
still a movement below 1280 px, which this round excludes.

The fix is not a smaller number, it is the right instrument: `useIsWide`, whose own comment names
exactly this case — *"für die Fälle, in denen der Unterschied NICHT im Layout liegt, sondern in der
DOM-Struktur selbst — und die kann keine Media Query beantworten."* Below the threshold the wordmark
is now a single text node again, the same one as before. **The CSS half stays anyway**: `.as-brandgrid`
is `display: none` in the base rule and visible only inside the desktop section, so a hook that ever
reported `true` too early still could not put a box on the phone.

### 2.2 The machine half — and the gate's wording is too coarse for this screen, not too strict

**The raw comparison is not zero, and reporting it as green would be wrong.** 160 cells,
`evidence/C2/after` against `evidence/C1/baseline`, `scripts/surface-delta.mjs`, run bare:

```
  compared 160 cells, 24309 matched nodes
  unmatched nodes: 160 pre-registered (H-c), 1600 elsewhere
  2750 deltas          exit 1
```

**Five surfaces are at zero, and they are the five that matter for the trap:** `skill-choice`,
**`run-stage`**, `perk-choice`, `architect`, `victory` appear nowhere in the report. The run replaces
the hub, so those captures contain none of it — **the wordmark trap did not fire**, and that is the
explicit requirement, met on the raw numbers rather than after any filtering.

**The other eleven are menu overlays, and the hub is standing behind all of them.** The survey
navigates from the hub; an overlay renders on top of it and the hub's DOM stays mounted. So a node
added to `.hub-play` shifts the structural path of every sibling after it, in eleven cells at once,
without any of those eleven screens having changed. Measured, not assumed
(`evidence/C2/whose-subtree.mjs`, run with the **options** overlay open):

```
  options open: true · hub still in the DOM behind it: true
  0/0/2/0/5/0  ->  BODY / min-h-screen / app-root / …grid / hub-root / hub-pair / hub-play
     0  H1   as-wordmark            <- unchanged
     1  DIV  as-lockup              <- ADDED by this commit; every index below moved up one
     2  DIV  …bonus lane            (was 1)
     3  DIV  …tutorial offer        (was 2)
     4  DIV  …play group            (was 3)
     5  DIV  …seed / leaderboard    (was 4)
```

**Every one of the 2750 deltas and all 1600 unmatched nodes lie under that one prefix** — checked by
counting rather than by reading: `0` delta paths and `0` unmatched paths fall outside it.

**An explanation is not a gate, so it was turned into one.** `evidence/C2/outside-the-hub.mjs` filters
both matrices down to the nodes **outside `.hub-play`** and runs the comparator again on what is left:

```
  before: 23979 nodes kept, 1210 dropped as .hub-play's
  after : 23979 nodes kept, 1210 dropped as .hub-play's
  compared 160 cells, 23979 matched nodes
  unmatched nodes: 0 pre-registered, 0 elsewhere
  ZERO computed deltas on the four surface axes.        exit 0
```

> **That is a stronger statement than the gate asked for.** Not *"every surface but `hub` at zero"* —
> **every node but `.hub-play`'s at zero, `hub` included**, across sixteen surfaces, five viewports and
> two languages.

**And inside `.hub-play`, nothing moved either except by insertion.** The head-zone probe records every
child's layout height before and after: `101 · 68 · 82 · 139 · 62` becomes
`101 · **109** · 68 · 82 · 139 · 62`. Every pre-existing child keeps its height to the pixel; one row
was added. The 2750 property "deltas" are the comparator holding node *N* of one run against node
*N+1* of the other — an artefact of the shift, not a movement.

**Both sides dropped the same 1210 nodes**, which is worth one line: the surface probe records nodes
that paint on one of the four axes, and none of the added ones does — the lockup has no background,
the tagline none, and an SVG's `fill`/`stroke` is on no axis of §2c. So the added row is invisible to
this gate by construction, and §3 measures it directly instead.

## Part 3 — the composition, measured against C1's predictions

### 3.1 What C1 predicted from a stand-in, and what the real one costs

| | C1, from an inserted stand-in | C2, measured |
| --- | --- | --- |
| `.hub-play` at 1280 × 720 | 438 → **566** | 438 → **561** |
| free height left in the left column | 139 | **144** |
| page overflow | 0 | **0** |
| the mark | 47 × 77 layout px | **47.33 × 76.91** |

**C1 was five pixels pessimistic, and the reason is worth the line** (C2-F11). It modelled the
tagline and the mark as **two rows** in `.hub-play`, so it paid the 14 px row gap twice. The shipped
composition is **one** flex child — `.as-lockup`, 109 px, carrying both with a 10 px gap between them
— so it pays the row gap once. 109 + 14 = 123 against C1's 128.

**Every other number C1 put in front of the owner held**: the mark's height, the page cost of zero,
and the fact that the left column never becomes the taller of the two.

### 3.2 The lockup reads as one block, and that is a measurement here

Three elements read as one when they share a centre. Measured as each element's centre against the
column's centre, at all five viewports and in both languages:

| | wordmark | tagline | mark |
| --- | --- | --- | --- |
| off-centre, worst case across ten cells | **0.01 px** | **0.01 px** | **0.01 px** |

The centring is `align-items: center` on `.hub-play` and nothing else — no wrapper, no second rule.
C1 measured why that is enough (C1-F13): of the column's five children it moves exactly one.

### 3.3 The mark, on two decks

The mockup was rendered with **one** deck and there are 52. Both ends of the range the design's own
open point is about:

| | Thron I `#8f0f2a` (darkest named) | Obsidian `#e8edf5` (brightest) |
| --- | --- | --- |
| `--deck-a1` reaching the mark | ✓ | ✓ |
| mark colour | `rgb(143, 15, 42)` | `rgb(232, 237, 245)` |
| page overflow, 1280 × 720 and 1920 × 1080 | 0 / 0 | 0 / 0 |

**Getting there found a hole in the harness** (C2-F01). The first run rendered both decks in the same
cyan, and the probe reported an empty `--deck-a1` without comment. The cause is not this file:
`resolveSkinId` hands back `"default"` for any deck the profile has not unlocked, so a **fresh
profile has no deck colour at all** — and the survey seeds a fresh profile. **No `hub` cell in any
matrix this round has ever carried a deck colour.** Here the unlock is satisfied the way the game
satisfies it (a won week for Thron, an owned pack for Obsidian), and an empty `--deck-a1` now fails
the cell instead of being printed as a blank.

### 3.4 The letter — geometry verified, legibility not claimed

The design's central claim is that the I reads as a letter made of eight cells. **The geometry is
faithful and checked**; whether it *reads* is a visual judgement, and an agent does not report a
visual result as approved.

| | design | measured at 1280 × 720, after `zoom: 0.85` |
| --- | --- | --- |
| cell | `.09em` = 7.92 px | 6.73 device px |
| border | `.012em` = 1.06 px | **0.90 device px** |
| gutter | `.022em` = 1.94 px | 1.65 device px |
| column | `.874em` = 76.91 px | 6.73 × 65.4 device px |
| lit cells, of eight | 1, 4, 7 | **3 hot, 5 quiet** ✓ |

**The sub-pixel border is the mechanism to know about.** An unlit cell is a 0.9 px ring at 22 % white,
which composites to roughly 76/255 over a ground near 26/255 — present, and much quieter than the
solid stems beside it. So the column reads as a segmented, part-lit bar rather than as a stem, which
is what the design asks for; how far that carries at 1280 is the owner's call.

**Four alternatives are built and captured at true 1×**, not described, so answering costs one look:
`evidence/C2/owner/wordmark-1x-de-*.png` — as designed · the unlit cells at the design's own *mid*
tone · a stronger neutral edge · a filled cell · a thicker ring. **What ships is the design as
written.**

### 3.5 The tagline

| | |
| --- | --- |
| role | `text-body-lg` — 15.5 px against the design's 15, no size introduced (C1-F11) |
| letter-spacing | `.05em` = 0.775 px, as the design gives it |
| colour | `#9a9aa6`, dots `#5c5c68` |
| rendered width, 1280 | de **213** layout px · en **168** |
| catalog | `start.tagline`, one key per file, closing period in **both** — Q3a |

**Neither colour is a new value in the tree** (C2-F04). `#9a9aa6` already carries muted body text at
four JSX sites; `#5c5c68` carries exactly this role — a separator quieter than the text beside it —
at six sites in `index.css`. So this adds **one call site each**, not two ink values. Ink is not one
of §2c's five axes and is counted rather than migrated in this round; C4 records the number.

*Noticed while checking that:* `index.css` also carries **`#9a9aa4`**, which is `#9a9aa6` with two
units off the blue channel. Not touched — collapsing it would be an ink change this round does not
make — and named here so the successor inherits a measurement rather than an impression.

### 3.6 The wordmark got narrower, not wider

| | before | after |
| --- | --- | --- |
| `AUTOSTICH`, layout px in a 700 px column | 639 | **632** |
| `AUTOTRICK` | 634 | **627** |
| collision point with the column gap | 96.4 px | **97.5 px** |

The cell column is **7 px narrower** than the I glyph it replaces, so the mark buys back a pixel of
the headroom C1-F12 measured away. Q6 (88 px) is unaffected either way.
