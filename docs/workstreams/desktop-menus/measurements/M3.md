## Part 2 — The zero-delta gate, and where it is claimed

**Where a zero delta is claimed:** on every surface that is not `upgrades`. This task changes one
screen, and the machine half exists to prove that the vocabulary migration did not move the other
sixteen while doing it.

**Where a zero delta is NOT claimed, and must not be:** on `upgrades` itself. This is a Tier C task —
it absorbs an approved redesign, so pixels move there by design as well as by migration. A zero
delta on that surface would mean the redesign had not been built.

```
node scripts/viewport-survey.mjs --out docs/workstreams/desktop-menus/evidence/M3/after
node scripts/surface-delta.mjs docs/workstreams/desktop-menus/evidence/M2b/after \
                               docs/workstreams/desktop-menus/evidence/M3/after
```

**Result: `evidence/M3/delta.txt`, 160 cells, 24747 matched nodes, 5269 deltas.** The comparator's
standing warning governs how it may be read:

> Surfaces only. Control states are not captured and are verified by hand.

**The claim as first worded — "zero delta on every surface that is not `upgrades`" — is too strong,
and the run is what corrects it.** Three surfaces carry deltas, and only one of them is this task:

| surface | deltas | what it is |
| --- | --- | --- |
| `upgrades` | 2811 | **by design.** Tier C absorbs an approved redesign; a zero here would mean it had not been built |
| `guide` | 2410 | **the same screen, seen underneath the overlay.** Not a change to the Guide |
| `options` | 48 | **pre-existing drift, inherited from the baseline gap.** Not this task |

**Why `guide` moves without the Guide changing.** The survey reaches it *through* this screen —
`viewport-survey.mjs:105` navigates `{tile:0}` → `.up-navrow` → `.up-page-guide`, so `GuideOverlay`
is captured mounted over the upgrade screen and my redesign shows through it. This is not inferred
from the navigation alone: the delta *contents* are unmistakably this screen's own changes —
`rgba(150,150,170,.14)` → `rgb(42,42,52)` is the `--ed-quiet` edge migration, `box[h] 43.25 → 44` is
the click-target fix of commit 4, and the deck accent moves to the §3.4 target-brightness mix. The
count is 241 in **every one of the ten cells**, which is what a structural change to one shared
screen looks like and what noise does not. M3-F05 anticipated this; the run confirms it.

**Why `options` moves, and why it is not mine.** English only, two sizes only, and every one of the
48 is `box[w]` or `box[x]` — pure reflow, no colour, padding or radius. Cause found in the baseline
gap rather than guessed: between M2b's matrix (`d2b2143e`) and this task's base (`cf7c3083`),
`src/i18n/en.js` changed `options.float.desc` from *"(FIERCE/BRUTAL/INSANE/GODLIKE)"* to
*"(NICE/BRUTAL/INSANE/GODLIKE)"*. Two characters shorter, English only, on the options screen — which
is the whole of the 6.84 px narrowing. The base commit names this itself: *"Merge dev into
feature/desktop-menus — take the design documents, **and the drift with them**."* Excluded
independently as well: this task's CSS diff touches no `.op-*` selector, and every i18n key it
changes is `upgrades.*`.

**So the gate passes in substance.** No surface moved because of M3 except `upgrades` and the view of
`upgrades` underneath the guide overlay. The other fourteen are byte-identical.

**Two independent full runs produced this same result** — 5269 deltas with the identical per-surface
split — which also settles a hazard that was live while they ran. A build was made during the first
run, the exact contamination this section warns about. It turned out harmless because the entry chunk
is content-hashed and resolved to `index-B2CbhMu1.js` across every rebuild, so the bytes swapped
under the server were identical; but that is an argument after the fact, and the second run is the
one the record rests on. `en/1280x720/architect` and `en/1280x720/victory` were unreachable in the
first run and reached in the second — transient, not a regression; all 160 cells are reached now.

Both halves still sit inside ISO week 35 (H-d), so the clock is not a factor.

**Three runs were started and thrown away before this one, and the reason belongs in the record
because the next worker will hit it too.** `vite preview` serves `dist/` from disk, so any
`npm run build` while a survey is running swaps the bundle underneath it: the early cells measure the
old build, the late cells the new one, and the matrix becomes a blend of two states that never
existed together — green, plausible, and meaningless. All three were killed the moment it was
noticed and their output deleted rather than compared. **The survey must be the last thing that
runs.** That is why the sequence above ends the work and is not followed by another build.

The same hazard has a second face, and it is why every measurement in this record is trustworthy:
the geometry probe verifies that the entry-chunk hash the server returns matches the one on disk
*before it measures anything*, and aborts if they differ. A preview server left running by an
earlier session on the shared worktree — there was one, from 01:02 — is otherwise indistinguishable
from a fresh one.

## Part 3 — The decision block, re-measured

**This is the part the contract calls the load-bearing one, and it does not confirm the document.**

### 3.1 The height arithmetic — the premise does not survive a `main` build

The design document opens by computing `.up-root` at 1080 px from *"Kopf 172 + Zweig 808 +
Legende 42"*, and the whole "costs no height" argument rests on it.

| term | document | **measured, `cf7c3083`, 1280×720** |
| --- | --- | --- |
| `.up-root` | 1080 px | **720 px** — it fills the viewport; it is not a 1080 px budget |
| head | 172 px | **74.1 px** |
| branch (`.up-branch`) | 808 px | **absent from the DOM** |
| legend | 42 px | **19.5 px** |

**M3-F01 — all three terms are stale, and the fourth is a category error.** The figure is inherited
from the comment at `.up-root` in `index.css`, which was written before the navigation column
existed. `UpgradeScreen.jsx` switches between two *render paths*, not two arrangements: at ≥1280 px
`wide` is true and `.up-desk` renders, so `.up-branches` and `.up-branch` are not in the tree at all.
Measured at 1280×720, 1536×791 and 1100×800: branch boxes 0 / 0 / 2.

**The conclusion the document draws from it is nevertheless right, for a different and measurable
reason.** The screen has almost no height to spare — not because it must fit in 1080 px, but because
`.up-card` is clamped to `height: 100%` and the content scrolls inside it. At the design anchor the
node grid was already scrolling **2.71×** before anything was touched. So the document's instinct was
sound and its arithmetic was not, and building against the arithmetic would have been building
against a number that no build produces.

The document says of the head: *"Was das an Höhe kostet: nichts."* It also mandates the Kopf-Kanon,

| `.up-head` | 74.1 | **98.3** | **+24.2** |
| `.up-desk` (everything below the head) | 617.9 | **593.7** | **−24.2** |

**M3-F02 — the two claims in the document cannot both hold, and the head is where they collide.**
The readout→chip swap really does cost nothing: two lines of grey text out, a labelled reading and a

This single number explains **every** downstream figure in §3.3 landing short of its prediction, and
it explains them consistently: 617.9 − 593.7 = 24.2 exactly.
