## Part 2 — re-measuring the designs' predictions

**Four design documents have gone to a worker in this round and all four failed the same way: their
observations held and their predictions did not.** So every number in both documents was re-measured
in a production build before a line was written, at all five viewports in both languages.

`evidence/M9/measure.mjs` is that harness. It exists as its own script rather than as a survey cell
because of H-c: the welcome screen is only reachable from an **empty** `localStorage`, which is the one
state `viewport-survey.mjs` deliberately never has. It imports MH2's promoted `survey-stub.mjs`, so it
runs with the pinned clock and answers `autostich_scores` locally, and it verifies the served bundle
against `dist/` before and after — the same three properties the survey now has.

### 2.2 `erststart-redesign.md` — the two predictions that moved

**M9-F01 — the card is 900 × 444 in English and 900 × 429 in German.**

| | 1280×720 | 1400×700 | 1536×791 | 1600×900 | 1920×1080 |
| --- | --- | --- | --- | --- | --- |
| **en** | 900 × 444.17 | 900 × 444.17 | 900 × 444.17 | 900 × 444.17 | 900 × 444.17 |
| **de** | 900 × 429.05 | 900 × 429.05 | 900 × 429.05 | 900 × 429.05 | 900 × 429.05 |

The document says *"die Kartengröße 900 × 444 px, die bei allen drei gemessenen Größen identisch ist"*.
**That is true and it is incomplete.** The size is identical across every viewport — the observation
holds exactly — but it is not identical across **languages**: German is 15.12 px shorter, because
`name.hint` wraps to two lines in English and one in German. 444 is the English figure, and English is
what a first-start screen shows by default, so the document measured the state it describes. The
number is not wrong; it is one of two. **Consequence:** the contract tunes in German, so the working
figure is 429, and both must be re-checked after the subline lands — it changes exactly this wrap.

**M9-F02 — the language control's conclusion is stale; its observation is not.**

The document says that once the divider overwrites the right button's state edge, *"übrig bleiben sechs
Punkte Flächenunterschied"* — that surface alone is left to carry the choice. Measured, both languages:

```
active    background rgb(25,25,34)   colour rgb(234,244,255)   box-shadow inset 0 -2px 0 rgb(38,198,230)
inactive  background rgb(19,19,24)   colour rgb(154,154,168)   box-shadow none
```

**The active half already carries a 2 px bottom edge in the deck colour** — which is precisely the
signal the document proposes to add (*"plus `inset 0 -2px 0` in der Deckfarbe"*). It was built by the
`#willkommen-ton` pass (`index.css:4717`). So what remains is not six points of surface; it is six
points of surface **and** the deck underline. The document's *direction* is right and already half
travelled — nothing it recommends is wrong in sign.

### 2.4 `feedback-redesign.md` — the problem statement that no longer describes the screen

**M9-F03 — all three parts of the head complaint are stale at ≥ 1280 px.**

The document's *Ausgangsproblem* item 1 says the close button sits in its own `ActionBar` **above** the
title, the title is **centred**, and the readout stands in its own grid column **behind a vertical
rule**. It scopes itself to *"die Fassung ab 1280 px"*. Measured there:

| claimed | measured at 1280 |
| --- | --- |
| `ActionBar` above the title | `.fb-bar` is grid **column 3, row 1** — beside the title, `x = 1011`, same `y` as the readout |
| title centred | `.fb-head { text-align: left }` in the desktop block |
| readout behind a vertical rule | `.fb-readout { border-left: 0; padding-left: 0 }` (`index.css:4804`) |

The `#feedback-ton` pass had already done this. The document describes the **phone** composition, which
is what the head still is below 1280.

**M9-F04 — the kind selector is already the segmented the document asks for, at the wrong height.**

The document asks for *"eine Segmented-Variante über die volle Panelbreite … 44 px hoch, aktiv =
hellerer Grund und 2-px-Unterkante in der Deckfarbe"*. Measured: one shared contour spanning the full
592 px panel width, active `rgba(32,32,44,.95)` with `inset 0 -2px 0 var(--deck-a1)`, inactive
`rgba(19,19,26,.9)`. **Everything but the height** — it stands at **37.33 px**, not 44.

**M9-F05 — the run-reference row already carries the target surface.**

The document asks for the options row surface, `rgba(15,15,21,.72)` with `1px solid
rgba(150,150,170,.12)`. `.fb-run` measures exactly that today. What differs is radius (12 vs the
document's 8) and padding (13/14 vs 11/13). The two **input** fields are the ones still on the special
values the document asks to retire.

### 2.5 What this confirms about the vocabulary

**The load-bearing result of this task, and it is a confirmation rather than a discovery.** Both design
documents were written against `design-sprache.md`, independently of §2c's ladder. Their literals land
on existing tokens **exactly**:

| Design asks for | §2c token | value |
| --- | --- | --- |
| segmented inactive `rgba(19,19,26,.9)` | `--ctl-face` | `rgba(19, 19, 26, .9)` |
| segmented active `rgba(32,32,44,.95)` | `--ctl-face-on` | `rgba(32, 32, 44, .95)` |
| segmented border `#3a3a44` | `--ctl-edge` | `#3a3a44` |
| radius 8 | `--rd-md` | `0.5rem` |
| panel radius 14 | `--rd-lg` | `14px` |
| panel tint 9 % / 5 %, border 26 % | `--sf-deck` · `--ed-deck-panel` | the same recipe |
| row padding 11 / 13 | `--in-tight` · `--in-snug` | `11px` · `13px` |

**Not one of these is a coincidence and not one needs a new token.** The two ladders were derived from
the same tree by two different routes and met.
