### Q1 — The four surface steps, as derived

Every value is one already standing in the tree, so commit 1 moves nothing. The names are new. Each
step is the value the **largest coherent group of boxes in that role** already carries — derived by
counting call sites, not by picking pleasant numbers.

| Step | Value | Derived from | Where you see it |
| --- | --- | --- | --- |
| `--sf-sunken` | `#141320` | `MENU_PANEL` — 12 sites | an inset tile inside a panel |
| `--sf-base` | `#17171c` | `.as-panel` — 30 sites | the neutral panel fill |
| `--sf-head` | `#1b1a24` | `STICKY_HEAD_BG`, `PANEL_BG` | a sticky head |
| `--sf-raised` | `#1b1a24 → #141019` | `MODAL_CARD`, `PANEL_CARD` | the card that holds a screen |

**Recommendation: accept as derived.** Three things fall out of it that are worth having:

- the ladder is monotone — sunken darkest, head lightest;
- `--sf-head` is *defined* as `--sf-raised`'s opening stop, so the head/card seam is invisible by
  construction rather than by two numbers someone keeps in step by hand;
- `--sf-base` is `#17171c`, which is already the dark half of `--deck-border`'s colour mix. The tree
  had written its panel ground down twice, in two unrelated places, with the same value. Now it is
  written once.

One value did **not** become a step. `#141419` — `phasePanel()`'s default base — is the application's
own background (`html, body`). It is what a panel *sits on*, not a panel, so it is `--sf-ground`,
outside the ladder. That also explains what it was doing: an inner structure box on the ground colour
reads as a hole punched in the card rather than as another layer stacked on it.

### Q2 — Two of those steps are nearly the same colour

`--sf-sunken` (`#141320`) and `--sf-base` (`#17171c`) are three or four units apart per channel. Side
by side they are the same dark, differing mostly in that one leans blue and the other neutral. They
are two steps today because the tree has two values, and collapsing them would move the end screen,
the statistics screen and the architect — none of which this task may touch.

**Recommendation: keep both, and decide at the end of the round.** By M11 every screen will have said
which of the two it actually wanted; that is a better basis than a guess made against one modal.
Collapsing them later is one line in the vocabulary and no call site changes — which is exactly the
point of having one.

### Q3 — The one thing that moves on the Options screen

The three panels' top padding goes from **16 px to 18 px**, so all four sides read `--in-base`. It is
the only inset on that screen that was not already a ladder step. Everything else on Options adopts a
token at its current value.

**Recommendation: accept.** 2 px of extra headroom on three panels, and the panel stops being the one
box on the screen whose padding is four different numbers.

*Not in this block, deliberately: the mechanism, the commit order, the acceptance viewports and the
axis caps are decided (contract, *Approved architecture*). No new typography role is needed — the
Options screen uses seven existing size tokens and this task changes none of them.*

### A second baseline, taken because the inherited one cannot answer this task's question

The `#typo` set measures **geometry and type**: page scrolling, overflow, truncation, and the size,
weight and family of every text node. It does not record a single background, border, radius or
shadow — which is exactly and only what commit 1 changes.

Running it before and after a conversion from `#1b1a24` to `var(--sf-head)` would report zero deltas
whether the token resolved correctly or did not resolve at all. **A gate that cannot fail is not a
gate**, so this task adds the instrument its own claim needs:

| File | What it is |
| --- | --- |
| `scripts/surfaceProbe.js` | a second probe: computed fill, background image, border colour/width/style, radius, shadow, padding, outline, opacity, colour and box, for every painting element, keyed by the same structural path `surveyProbe.js` uses |
| `scripts/surface-delta.mjs` | the comparator: two matrices in, every computed difference out, exit 1 if there is one |

It is **additive**. `surveyProbe.js` is shared with `#viewport-1280` and its output shape is committed
evidence there, so the surface probe writes its own `surface` key alongside rather than editing the
first probe. An older `matrix.json` simply has no such key.

**Recorded as a departure from the contract's *Expected file surface*** (`scripts/**` is not listed
there), per that section's own instruction to record and report rather than to block.

*Both files are committed with commit 1.*

## Part 2 — The zero-delta gate

**The claim: commit 1 moves no pixel on any of the 15 surfaces, at any of the 5 sizes, in either
language.** Instrument: `scripts/viewport-survey.mjs` with the surface probe of Part 1, compared by
`scripts/surface-delta.mjs`. Geometry tolerance is **zero** — accepting sub-pixel drift here would
accept exactly the defect class a padding token is most likely to introduce.

The gate ran **three times**, and the two failures are kept in this record rather than tidied away:
they are what the gate is for, and both defects were mine.

### Run 1 — FAILED, 135 deltas, two real defects

| Cause | Deltas | Surfaces |
| --- | --- | --- |
| Accent composites frozen at `:root` (MENU-15) | 120 | architect, perk-choice, skill-choice |
| Padding on the shared `#eckig` hook (MENU-16) | 15 | victory |

**MENU-15 — a token that reads another token only sees values present where it is *declared*.**
`--sf-cone`, `--ed-accent`, `--el-halo` and `--hl-accent` were written as `:root` tokens reading
`var(--ac-rgb)`, with `phaseCard()` setting `--ac-rgb` per element. Measured in a browser, three
cases:

| Setup | Computed result |
| --- | --- |
| token declared at `:root`, `--ac-rgb` set on the element | **`rgba(155,130,240,.14)` — the fallback** |
| the same token declared on a **class the element carries** | `rgba(224,85,85,.14)` — resolves |
| a **flat** token redefined on the element (planning report §2.1 case B) | `rgb(224,85,85)` — works |

A custom property that references another is substituted **on the element that declares it**, and
the resolved string then inherits. The architect went blue → violet, the perk choice red → violet,
and `PhaseHairline` lost its background entirely, because `--hl-accent` had no fallback and the whole
gradient went invalid.

**Planning report §2.1 is not wrong and its conclusion stands.** Case B redefines a *flat* property
on the element, which works — `.cz-stage` still relies on it and the `!important` deletion holds.
What §2.1 never claimed, and never tested, is the *nested* case. That was this task's assumption.

*Resolution:* anything accent-coloured decomposes. Every length and every alpha is a scalar token;
only the colour is interpolated in `modalStyle.jsx`, where `PHASE_ACCENTS` already lives as a
documented exemption. No value moved — only where it is assembled.

**MENU-16 — the `#eckig` hook is shared with three buttons that are not `ActionButton`s.**
`padding` was put on `.as-actbtn`. `GameOver.jsx` hangs that class on three buttons it builds **by
hand** for the radius alone (lines 162, 229, 234), two of which carry `py-3` / `py-2.5` and **no
horizontal padding at all**. An unlayered rule beats a Tailwind utility whatever the source order, so
all three silently gained 16 px. The `<ActionButton>` call sites had been checked and none passes a
padding utility; the hand-built ones were missed.

*Resolution:* padding rides on `as-actbtn-pad`, emitted only by `ActionButton`. The radius stays on
the shared hook — all three hand-built buttons carry `rounded-lg`, whose value `--rd-md` equals.

### Run 3 — the `--ui-scale` multiplier, proven separately

Contract addendum §1 puts a geometry multiplier on every length. It is diffed against **run 2**, not
against the baseline, so "the conversion is value-preserving" and "the multiplier is value-preserving"
stay two checkable claims rather than one.

Reproduce either run from the committed evidence:

```bash
node scripts/surface-delta.mjs docs/workstreams/desktop-menus/evidence/M1/before                                docs/workstreams/desktop-menus/evidence/M1/after-c1          # run 2
node scripts/surface-delta.mjs docs/workstreams/desktop-menus/evidence/M1/after-c1                                docs/workstreams/desktop-menus/evidence/M1/after-c1-uiscale  # run 3
```

Ahead of it, the specific risk was measured directly: does `calc(N * 1)` serialise identically to `N`
in computed style? Tested across `border-radius`, `padding`, `box-shadow` (negative spread included)
and `radial-gradient` axes, in `px` and in `rem`: **identical, every property.**

**Result — PASSED.**

| | |
| --- | --- |
| Cells compared | **150**, 0 unreached |
| Matched nodes | **24 167** |
| Computed element deltas | **0** |
| Unmatched nodes | **0**, on any surface |
| Token declarations differing in text | 12, all of them the multiplier itself |

The twelve are `--ui-scale` appearing plus eleven tokens gaining a `calc(… * 1)` wrapper —
`--btn-pad-x/y`, `--el-float`, `--el-halo-blur`, `--el-modal`, `--rd-md`, `--rd-shell`,
`--sf-cone-h`, `--sf-cone-w`, `--sf-cone-w-phase`, `--sf-cone-modal`.

**The comparator was changed after this run first came back red, and that is stated here rather than
left to be discovered.** It had been counting the `:root` token table as pixel deltas — 1650 of them,
every one a text difference of the form `1rem` → `calc(1rem * 1)`. The token readout records a
custom property's **specified text**; the gate is about **computed** values on elements. Those are
two different measurements and only the second is the acceptance criterion.

Three things keep that from being a loosening:

- the element gate is untouched and still fails on any difference, at zero tolerance;
- the `calc` equivalence was proven **before** this run, by the dedicated serialisation probe above,
  so the verdict does not rest on the comparator change;
- every one of the twelve tokens has live consumers among the 24 167 element rows — `--sf-cone-modal`
  through `MODAL_CARD`, `--el-float`/`--el-modal` through `phaseCard()`, `--rd-md` and `--btn-pad-*`
  through the two button hooks — so a wrong **value** would still surface as an element delta. The
  tokens that have no consumer are precisely the ones Tailwind prunes, and they never reach the table
  at all.

The table is printed in full on every run and never elided.

**Verdict: the multiplier is value-preserving. Commit 1 moves no pixel.**
