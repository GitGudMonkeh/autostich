### The two that went red because the migration succeeded

Both spelled the number where the rule now names the step. **Rewritten to the invariant, not to a
second spelling** — which is M5's repair applied twice more, and the invariant has three parts:

1. the rule reads **exactly this rung** — its declared value, resolved through the `@theme` block, equals the resolved `var(--rd-sm)` (or `var(--el-flat)`);
2. **the rung still carries its value** — the resolution contains `6px`, or is exactly `none`;
3. **and it is not the neighbouring rung** — the negative probe. Without it the radius assertion would pass on `--rd-md` and the shadow assertion on `--el-rest`, and the banner would be rounder than intended and have its glow back, green.

The instrument is `cssTokens.js`'s `resolve()`/`themeTokens()`, the same one `fx-panel.test.js` uses
at `.cz-stage`, and both guards read the rule **with comments stripped** — the reasoning at the site
names both tokens, and a guard its own comment can satisfy checks nothing.

### M11-F06 — the third one went red for a reason worth writing down

`overlay-nesting.test.js` decides *"is this overlay portalled?"* from the **260 characters before the
class literal**. A three-line comment between `overlayPortal(` and the element pushes the call about
330 characters away, and the guard reports an un-portalled overlay that is in fact portalled.

**Nothing was weakened.** The invariant was never violated, so **the source moved**: the comment now
stands above the `return`, and the reason is at the site. Widening the window would have been the
wrong repair in the literal sense — a wider window is more likely to find *someone else's*
`overlayPortal(` and call a genuinely un-portalled overlay fine. **A proximity window is a guard that
trades precision for simplicity, and a comment is enough to spend it.** Reported for the successor
rather than fixed from inside this task, because the fix is structural (does the enclosing `return`
begin with `overlayPortal(`?) and belongs to whoever owns that guard.

**1. The vocabulary held to the last file, and the last file is the one that proves it cheaply.**

wash, a scrim and a dim are the values most likely to differ only in opacity.

**6. One flaky cell makes every later cell incomparable, and MH2's run counter is what says so**
(M11-F10). A single `victory` walk timed out at the formation phase, and the run it never finished
left **81 of the 160 cells carrying a different run count**. Only `stats` renders run history, so the
symptom was five cells wide — **88 geometry deltas and 9 unmatched nodes on a screen nobody had
touched** — while the cause was eighty-one. `runs: {entry, capture}` named all of them. **Without that
field this reads as a real regression on `stats`.** The re-run is clean; the lesson is that the matrix
is a *sequence*, not a set, that its own instrument already knows it, and that **the symptom of a
sequence effect is far narrower than its reach** — the next one may land on a screen that shows
nothing at all.

**7. What is not open.** Nothing downstream inherits from these four — they render only M1's
primitives. `.up-banner` has stopped being an exception in the allowlist: the two `.up-` expressions
now partition the sheet, and a counter-check holds them to it. And the twelve `.as-edge-*` alphas,
the ink gap and MENU-39 leave this round exactly as they entered it — **counted, named, untouched**.
`.as-chip` / `.as-chiprow` (M6-F10) is the one member of the translucent-edge family still standing
outside every ratchet.
