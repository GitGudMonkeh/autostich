## 0. What was measured, and against what

**The baseline is `evidence/M7/after`**, named rather than re-derived, and the zero-delta gate in
part 2 is computed against it.

**And it is not enough for this task**, for the reason the contract states as hazard H-a: the survey
opens hub tile 2, which is the **board** entry on its default tab, and it reads the **live**
`autostich_scores` table. Two things follow:

1. the row count follows the network (TYPO-08), so the two halves of a comparison are not
   guaranteed to be the same tree;
2. the **ranked** entry — the ranked button, its cockpit, its week head and its rules tab — **is not
   in the matrix at all.** No survey cell has ever opened it. Everything the design document is
   *about* lives there.

So the survey stays untouched and produces the gate; a second harness produces the before/after
geometry of the screen the task redesigns.

| | |
| --- | --- |
| Harness | `evidence/M8/measure.mjs` — production build, real CDP viewport, **port 5189** |
| Board | `evidence/M8/seed.mjs` — a generated 20-row table, served by a `fetch` interceptor |
| Clock | pinned to **2026-08-24 12:00 UTC** in both halves |

Six views per size and language, and the six are the task: `board/global`, `board/week`,
`board/champions`, `ranked/week`, `ranked/champions`, `ranked/rules`.

### The board held still — H-a answered in code, not in prose

`fetchStubSource()` installs a `fetch` interceptor as an **init script**, before the module graph
runs, and answers every `autostich_scores` request from a fixed table. `leaderboardConfigured` stays
true, every code path is the real one, and the row count is the same number in both halves **by
construction** rather than by luck.

> **Row count, both halves: 20 and 20**, in all 60 cells of the harness — and **20 and 20** in the
> machine half as well (§2). The number is stated for both halves as the contract requires, and it is
> not a coincidence: see M8-F01 below for why it cannot move on this matrix at all.

### The clock, pinned

The ranked tab renders a live countdown that ticks every second, and the hub reads the ISO week
behind every overlay. `freezeClockSource()` pins `Date.now()` and `new Date()` — not
`performance.now()`, which React's scheduler reads and which a frozen monotonic clock would hang.
Both halves therefore carry the identical week label, the identical week seed and the identical
countdown string (`Reset in 6t 11h 59m 59s`), and neither half can be on the other side of a week
boundary.

### Two things the seeding cost, both worth the next person's time

> **M8-F02 — a seeded profile does not survive its first boot, and this is the second instance of
> M7-F02's defect class, one layer further down.**
>
> M7 found `maybeResetForEpoch` wiping a fresh namespace and stamped `as_reset_epoch`. That stamp is
> in this seed too, and it was **not enough**. A profile blob without `schemaVersion` enters
> `migrateProfile` (`storage.js:150`) at v0 and walks the whole chain; step v6 → v7 (#369) does this:
>
> ```js
> if (spent > 0 || hasOldNodes) { out.stichPoints += spent; out.stichSpent = 0; out.nodes = {}; }
> ```
>
> It is right for a real profile — the old tree's node ids are dead and the SP are refunded — and it
> is fatal for a seeded one. `nodes` is emptied, `rankedUnlocked()` goes false, and the ranked
> cockpit renders the **locked line instead of the play button**. Nothing errors. The first capture
> run measured that screen and looked entirely plausible; the play button is simply not in it.
>
> Stamping `schemaVersion: 11` fixes it. What makes it catchable is the assertion: `measure.mjs`
> **throws** when the ranked cockpit has no `.as-cta-primary`, exactly as M7's throws when the run
> list is empty. *A harness that cannot tell "different screen" from "same screen" has no gate.*

> **M8-F03 — port 5189 was occupied by a preview serving a DIFFERENT checkout, and the refusal is
> the only reason it was noticed.**
>
> `measure.mjs` refuses to run when something already answers on its port. It fired, and the process
> it found was
> `node C:\Code\Autostich\node_modules\vite\bin\vite.js preview --port 5189 --strictPort` — i.e. a
> preview of the **main checkout**, not of this worktree, orphaned (its parent was gone). Reusing it
> would have measured a bundle that has nothing to do with this branch, silently. **That is exactly
> the failure that cost M3 its gate, on the other port.** It was killed and the run repeated; the
> stop path in the harness now polls the port after `kill()` and warns rather than assuming.
>
> The contract's own table is the lesson, one row down: *does something answer on the port* is the
> wrong question. *Does it serve my bundle* is the right one, and refusing is the cheapest way to
> ask it.

> **M8-F01 — the row count is pinned at 20, and the reason is worth two paragraphs.**
>
> The contract requires the row count in both halves, because TYPO-08 records that this surface's

> table holds more than twenty rows. What the network can still move is the row *content* — names and
> scores — which changes text, not the node set. **That is why `leaderboard` showed zero unmatched
